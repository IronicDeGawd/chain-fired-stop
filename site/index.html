      Your stop-loss is only as alive as whatever holds it

      A stop-loss feels like a promise: price falls to a number, the position closes. But on most venues something has to be awake to keep that promise. Either the exchange's servers watch the price, or your own bot does. If that thing is down, slow or disconnected, the stop is just a number in a database.

      On Somnia the chain can keep the promise itself. A contract asks the chain to wake it up every few seconds. When it wakes and the price is at the stop, it sells. Nobody signs that transaction and nothing off-chain is running.

      The chain's sale is sent by the contract 0x09e201dAF194DdC18345bd26cb6fD23E954Cd565 itself, because Somnia delivers a reaction as a transaction from the subscription's owner. No wallet signs it.

      How the chain wakes a contract

      Somnia Reactivity lets a contract subscribe to events, including a system Schedule event that fires once at a chosen time. The contract books a wake-up 5 seconds out; each time it wakes it checks the price, then books the next one.

      function onEvent(address, bytes32[] calldata, bytes calldata) external {
    require(msg.sender == REACTIVITY, "only chain");
    (bool ok, uint256 mark) = pool.tryGetMarkPrice();
    if (ok && mark <= stopPrice) { _close(mark); return; }
    _scheduleNext(); // Schedule(now + 5 s)
}

      The contract must hold 32 STT when it books a wake-up (a spam check, not a fee). Each wake-up and the final sale are paid from its balance: a run like this costs about 0.09 STT.

      dreamDEX's own TP/SL on perps already work this way. The exchange's stop contracts are woken by the chain every 5 seconds, and each TP or SL holds 0.15 STT to pay for its trigger.

      Fine print

      The chain checks every 5 seconds, not continuously, so a stop can fire up to about 5 seconds after the price crosses (alarm plus block timing). It reads the exchange's mark price, which is smoothed, so a very short wick may not trigger it. This is testnet, with test USDso.
